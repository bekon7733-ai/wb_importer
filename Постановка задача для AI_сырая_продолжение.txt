Во вложении созданное тобой приложени в виде нескольких файлов. Приложени рабочее. Все отлично. Нужно его дополнить следующим функционалом: импортированием из Wilberries данных о Поставках. Для этого в API Wildberries существует 3 метода (запроса):
- Список поставок
- Детали поставок
- Товары поставки
Я их подробно последовательно расписал во вложенном текстовом файле "Запросы по поставкам". Нужно создать три таблицы в схеме "Wilberries" базы данных postgres. Так как объем данных по Поставкам значительно меньше, чем в финансовых отчетах, то можно предусмотреть только одну команду для импорта из Wilberries новых данных по поставкам, которых нет в базе данных. При запуске этой команды нужно предусмотреть проверку наличия таблиц в базе данных, и если их нет, то создать.
В запросе "Список поставок" есть поле "supplyID" с идентификатором поставки, который принимает значения null или целого числа. Давай сразу при импорте будем исключать поставки с null значением этого поля, так как в этом случае поставка только запланирована, а мы будем импортировать только состаявшиеся фактические поставки товаров на склады Wilberries.
Я не нашел поля "supplyID" в примерах запросов "Детали поставок", "Товары поставок". Если я прав, то добавь в эти таблицы данный вторичный ключ для связи между таблицами. Если же я ошибаюсь, и такие поля (которые играют роль вторичных ключей) уже существует в запросах "Детали поставок", "Товары поставок", то используй эти поля для связи между таблицами. Как я понимаю: сущности "Список поставок" и "Детали поставок" связаны один к одному (ну или можно установить один ко многим" для универсальности), а сущности "Список поставок" и "Товары поставки" связаны один ко многим. Проверь этот момент, и создай правильные связи в схеме "Wilberries" базы данных postgres.
Внеси изменения в файлы, в том числе, в файл с описанием приложения README. На выходе приведи по раздельности коды для каждого файла.
