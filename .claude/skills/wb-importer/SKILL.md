# WB Importer — руководство для работы с репозиторием

Консольное приложение: забирает отчёты реализации и поставки из API Wildberries и
складывает их в PostgreSQL (схема `Wildberries`, 7 таблиц). Тестов нет, сборки нет —
только Python-скрипты и `click`-команды. Документация и сообщения — на русском,
пиши так же.

## Карта кода

| Файл | Что внутри | Когда трогать |
|---|---|---|
| `main.py` | логирование в `wb_importer.log`, группа `click`, регистрация команд `cli.add_command(...)` | новая команда |
| `cli.py` | реализация всех команд (`cmd_*`), бэкап перед UPSERT, логика «с крайней даты» | поведение команд |
| `api.py` | `_request` (finance-api, пауза 65 с) и `_request_supplies` (supplies-api, пауза 3 с), обработка 401/402/429/400/404, пагинация | новые методы API, лимиты |
| `models.py` | модели SQLAlchemy: `ListMixin`/`DetailMixin`, `PERIOD_MODELS`, таблицы поставок; имена таблиц кириллицей | новые таблицы/колонки |
| `mapping.py` | `map_report_list`, `map_report_detail`: поле API (camelCase) → колонка БД, конвертеры `_to_date/_to_decimal/...` | новые поля API |
| `db.py` | engine, `init_db`, `upsert_rows`, бэкапы и экспорт в CSV | работа с БД |
| `config.py` | чтение `.env`, лимиты и задержки API | настройки |
| `Шаблоны API запросов/` | описания методов WB API, по которым построены таблицы | **сверяйся с ними** при изменении полей |
| `Постановка задача для AI_*.txt` | исходное ТЗ | понять замысел |

Связи таблиц: `СписокОтчетов…` 1→∞ `Детализации…` по `report_id`; `СписокПоставок` 1→1
`ДеталиПоставки` и 1→∞ `ТоварыПоставки` по `supply_id`. Ключи UPSERT: `report_id`, `rrd_id`,
`supply_id`, для товаров — `supply_id + barcode`.

Локальные папки, **не входящие в git** (не коммитить, не публиковать, без просьбы не менять):
`.env`, `backups/`, `exports/`, `wb_importer.log`, `Песочница/`,
`Резервное копирование версий приложения/`, `__pycache__/`. В них коммерческие данные продавца.

## Запуск

Окружение: Windows, Python вызывается как `py` (на Linux/macOS — `python3`).

```powershell
py -m pip install -r requirements.txt   # зависимости
py main.py --help                        # список команд — безопасно, сеть не нужна
py main.py init                          # создать схему/таблицы (нужен PostgreSQL из .env)
```

Команды с разной «ценой»:

- **Безопасные**: `--help`, `init`, `export-*`, `backup` — только локальная БД.
- **Ходят в API WB, но ничего не пишут**: `list` (всё равно долго — пауза 65 с на запрос).
- **Пишут в БД реальные данные**: `update`, `update-supplies`, `import`. Перед записью делают
  CSV-бэкап в `backups/`, но это рабочая база пользователя. **Не запускай их без явной
  просьбы.** Финансовые команды работают минутами-часами из-за лимита 1 запрос/мин —
  запускай с `run_in_background` и следи за `wb_importer.log`.

Проверить, что изменение хотя бы импортируется, не трогая сеть и БД:

```powershell
py -c "import config, models, mapping, api, db, cli, main"
py main.py <команда> --help
```

Не выводи и не копируй содержимое `.env` (там `WB_API_KEY` и пароль БД). Если нужно знать,
какие ключи заданы — смотри `.env.example` и `config.py`.

## Внесение изменений

Общие правила: следуй стилю соседнего кода (русские docstring и комментарии, эмодзи в
`print`, `logger = logging.getLogger("wb_importer")`), не добавляй зависимости без нужды,
не меняй задержки `REQUEST_DELAY`/`SUPPLY_REQUEST_DELAY` в меньшую сторону — WB вернёт 429.

**Новая команда CLI**
1. `@click.command("имя")` + функция `cmd_имя` в `cli.py`; в начале — `init_db()`, сессия в `try/finally: session.close()`.
2. Импорт и `cli.add_command(cmd_имя, "имя")` в `main.py`.
3. Пример запуска в README, раздел «Использование» (и строка в таблице «Какие задачи решает», если это новая возможность).

**Новое поле из API**
1. Найди поле в `Шаблоны API запросов/*.txt` (тип, формат).
2. Колонка в модели `models.py` (в миксин, если нужна и в сутках, и в неделе).
3. Строка в `mapping.py` с подходящим конвертером.
4. `create_all` **не добавляет колонки в существующие таблицы** — дай пользователю SQL
   `ALTER TABLE "Wildberries"."<Таблица>" ADD COLUMN ...;` и не выполняй его сам.

**Новая таблица**: модель в `models.py`, при необходимости — в `backup_all_tables`/экспорт
в `db.py`, обнови раздел «Структура базы данных» в README.

**Новый метод API**: функция в `api.py` поверх `_request` / `_request_supplies` (они уже
делают паузы и повторы), не вызывай `requests` напрямую.

## Поиск и исправление ошибок

1. Смотри хвост лога: `Get-Content wb_importer.log -Tail 80` (или `tail -n 80`). Ищи
   `[ERROR]`, `Traceback`, коды `401/402/429/400`.
2. Типовые причины:
   - `401` — неверный/просроченный `WB_API_KEY` или у ключа нет доступа «Финансы»/«Поставки». Код не чинить — сказать пользователю.
   - `429` — превышен лимит; проверь, не запускалось ли две команды параллельно и не уменьшены ли задержки.
   - `400` — неверный формат дат/тела запроса; сверь payload с `Шаблоны API запросов/`.
   - `psycopg2.OperationalError` — PostgreSQL не запущен или неверные `DB_*` в `.env`.
   - `UndefinedColumn` / `column ... does not exist` — модель изменили, а таблицу нет (см. `ALTER TABLE` выше).
   - `ValueError`/`InvalidOperation` при маппинге — WB поменял формат поля; поправь конвертер в `mapping.py`.
3. Воспроизводи минимально: вызови нужную функцию `mapping`/`api` из `py -c` вместо полного
   `update`. Для `mapping` можно подсунуть строку JSON из шаблона API — сеть не нужна.
4. Бэкапы перед UPSERT лежат в `backups/<Таблица>_<tag>_<время>.csv` — если данные
   испорчены, сообщи пользователю, какой файл восстанавливать; сам не восстанавливай.

## Обновление README

README — лицо проекта на GitHub, пишется для селлеров без опыта программирования.
После любого изменения, которое видно пользователю, сверь разделы:

- «Возможности» и «Какие задачи решает» — новые/удалённые функции;
- «Установка» → таблица параметров `.env` — должна совпадать с `.env.example` и `config.py`;
- «Использование» — каждая команда из `main.py` с примерами, опции совпадают с `--help`;
- «Структура базы данных» и «Структура проекта» — таблицы и файлы актуальны;
- вывод команд в примерах совпадает с реальным (например, какая отметка у загруженных отчётов в `list`).

Сохраняй тон, форматирование (таблицы, блоки кода `bash`, `py` вместо `python`) и язык.
Скрипт `scripts/check.py` ловит рассинхрон команд и параметров `.env`.

## Проверка и подготовка к публикации

Перед коммитом/пушем запусти проверку из корня репозитория:

```powershell
py .claude/skills/wb-importer/scripts/check.py
```

Она проверяет: компиляцию всех `.py`, импорт модулей, что все команды из `main.py` описаны
в README (и наоборот), что ключи `.env.example` = ключи в `config.py` и описаны в README, что
в git не попали `.env`, CSV/XLSX, логи, бэкапы и локальные папки, и что в отслеживаемых
файлах нет похожих на токены WB строк (JWT `eyJ…`) и реальных паролей в `.env.example`.

Затем вручную:
1. `git status` — нет ли неожиданных файлов (новые картинки вроде `img/` добавляй, только
   если они используются в README, и упомяни их в «Структуре проекта»).
2. `git diff --staged` — перечитай; убедись, что нет данных продавца (ID отчётов, суммы, баркоды
   из реальных выгрузок) в примерах и коде.
3. `requirements.txt` содержит все импортируемые сторонние пакеты.
4. Коммит — только по просьбе пользователя, сообщение на русском, в повелительной форме
   («Добавить импорт возвратов»). Пуш в `origin` (github.com/bekon7733-ai/wb_importer) —
   только после явного подтверждения.

Если секрет уже попал в историю git — не пытайся тихо переписать историю: скажи пользователю,
что ключ нужно **перевыпустить в кабинете WB**, и предложи варианты очистки истории.
